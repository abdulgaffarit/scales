# USA Salaries

Salary site built with Python + Jinja2. Deploys to Cloudflare Pages.

## Setup

```bash
pip install jinja2 markupsafe
python build.py
```

## Deploy

Push to `main` — GitHub Actions (`.github/workflows/deploy.yml`) builds and deploys.
It is the only production deploy path.

## Data: sources of truth

| File | What it controls | How it changes |
|---|---|---|
| `data/jobs.csv` | Which occupations exist, their URL slugs, titles and categories | **Edited by hand.** Source of truth. |
| `data/job_soc.csv` | The BLS SOC code behind each slug | **Edited by hand.** Source of truth. |
| `data/legacy_slugs.csv` | 301 redirects from old or retired slugs to current ones | Edited by hand; `build.py` generates `_redirects` and `cloudflare_bulk_redirects.csv` from it |
| `data/national_wages.csv`, `data/state_wages.csv`, `data/oews_meta.json` | BLS OEWS wage figures | Generated by `scripts/fetch_oews.py` |
| `data/raw/oesmYY{nat,st}.zip` | BLS OEWS source files | Downloaded manually from bls.gov (see `data/raw/README.md`) |

### Refreshing BLS wages (normal workflow)

1. Upload the new `oesmYYnat.zip` and `oesmYYst.zip` to `data/raw/` on `main`.
2. The **Refresh BLS OEWS Data** workflow runs `scripts/fetch_oews.py`, commits the
   regenerated wage CSVs and triggers a deploy.

This never changes `jobs.csv` or `job_soc.csv`. If BLS renames or splits an occupation,
update `data/job_soc.csv` (and add a redirect in `data/legacy_slugs.csv` if a slug changes).

### Changing the occupation catalog

Edit `data/jobs.csv` and `data/job_soc.csv` directly. When a slug is removed or renamed,
add a row to `data/legacy_slugs.csv` so the old URL 301s to its replacement. Never
redirect to `/` or `/salary/`, and only redirect to a page with the same occupation.

### Legacy generator scripts

`generate_from_bls.py`, `fetch_data.py`, `update_data.py` and `parse_bls_data.py` predate
the hand-corrected catalog. Running them would replace `data/jobs.csv` (`fetch_data.py`
also replaces `states.csv` and `cities.csv`) and can bring back retired slugs, outdated
SOC codes and removed occupations.

They refuse to run while `data/jobs.csv` exists. Pass `--force` only when you intend to
regenerate the whole catalog, then re-apply `data/job_soc.csv` and `data/legacy_slugs.csv`
before building. The check lives in `data_guard.py`.
